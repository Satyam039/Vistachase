# API inventory

Every HTTP endpoint of the Express backend (`backend/src/app.ts` mounts the routers in `backend/src/routes/`), as of commit `578ffdb` plus this branch. Generated by reading each route file, then checked by hand where the guard is not inline (file-level `router.use` guards in `admin.routes.ts` and `operations.routes.ts`, inline token checks in `account.routes.ts`).

**Cross-cutting behaviour (all `/api/*`):** CORS allow-list with credentials; `helmet` (CSP, HSTS 1 year); CSRF guard that refuses state-changing requests whose `Origin` is not allowed (`app.ts`); JSON body limit 1 MB; a JSON replacer that sends departure dates/times as `YYYY-MM-DD` / `HH:MM`; unknown `/api/*` → 404 JSON; central error handler. Session = `vc_token` cookie (httpOnly, SameSite=Lax, Secure in production, 7 days) or `Authorization: Bearer`. Rate limits use Redis (`rateLimitMiddleware(name, {maxRequests, windowSeconds})`).

Legend: **Guard** = who may call it. *public* = anyone. *user* = signed-in user, checked in the handler. *staff* = ADMIN, OPERATOR or DISPATCHER unless narrower roles are listed. **RL** = rate-limit bucket. **Val** = request validated with zod (`parseOr400`). **UI** = frontend file that calls it (none = API-only today).

## Static media

The frontend proxies `/media/*` here, but serves most files from its own `public/media` copy first (see `docs/TESTING_AND_PRODUCTION_READINESS.md`, CDN section).

## Contract notes and inconsistencies found

1. Hold token parameter: `GET ?holdToken=` vs `DELETE ?token=`. Keep both working if unified later.
2. Errors are mostly `{ success: false, error }`, but operations/account routes return `{ error }` without `success`. Clients should check the HTTP status.
3. Money: API sends **dollars** (`price: 199`); the database stores **cents**. `basePrice`, `price`, `childPrice`, `totalAmount` follow this.
4. Booking create returns 409 for every business refusal (sold out, closed, enquiry-only); validation errors are 400.
